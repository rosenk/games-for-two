# 0012 — Bundled dev за бавна връзка към preview

Дата: 2026-09-23
Статус: Прието

## Контекст

Vite dev preview през orb портала зареждаше 30 заявки, включително около 25 отделни JavaScript модула. Локалните отговори бяха бързи, но последователните вълни import-и струват много при висока латентност към dev сървъра.

## Решение

В `vite.config.js` включваме Vite 8 `experimental.bundledDev` за `serve`. Dev preview се обслужва с bundle, а `npm run build` продължава да създава същите production assets в `dist/`. `.amp/services.yaml` продължава да стартира `npm run dev`.

## Алтернативи

Само pre-bundling на зависимости не обединява многото собствени `src` модули; обикновен Vite dev запазва удобното обслужване на всеки модул, но и високия брой заявки. `vite preview` би сервирал production bundle, но изисква build след промяна и не замества dev workflow.

## Последствия

Порталното измерване след промяната показа 7 вместо 30 заявки и 2 вместо около 25 dev JavaScript файла; при ниската латентност на орба `load` намаля от ~519 на ~333 ms. Това не доказва конкретно време при друга мрежа. Режимът е експериментален и има различна HMR семантика, затова при проблем с обновяването на Svelte трябва да се преоцени. Production build-ът не се променя.
