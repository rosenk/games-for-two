# 0001 — Записване на архитектурните решения

Дата: 2026-09-23
Статус: Прието

## Контекст

Проектът има игрова логика, онлайн сесия и услуга за намиране на противник, но причините за бъдещи архитектурни избори не са записани на едно място. Само крайното състояние на кода няма да показва разгледаните компромиси.

## Решение

Записваме значимите нови архитектурни решения като номерирани Markdown ADR-и в `docs/adr/`, заедно с промяната, която ги въвежда. Проектното умение определя кога и как ги поддържаме; `AGENTS.md` изисква проверка за ADR при работа по кода. При замяна създаваме нов запис и свързваме стария, вместо да заличаваме мотивите му.

## Алтернативи

- Само README или коментари в кода: описват текущото поведение, но не запазват отделно контекст, алтернативи и последици на даден избор.
- ADR за всяка промяна: добавя шум и поддръжка без полза при локални поправки.

## Последствия

Причините за бъдещи решения остават проследими близо до кода. Значимите промени изискват и поддръжка на документация; малките поправки не изискват ADR. Не възстановяваме със задна дата недокументирани мотиви за вече съществуващи избори.
